# src/lib/offline — client-side offline persistence

IndexedDB storage for the offline visit flow, backed by **Dexie v4**. Runs in the browser and the Capacitor WebView (`client-only` guard — never bundled server-side). Kept deliberately separate from `src/lib/db/` (which is `server-only` Prisma).

## Why Dexie

Capacitor Preferences has a ~1MB soft key cap; Dexie/IndexedDB has no practical cap and behaves identically in the PWA and the native WebView.

## Modules

- `types.ts` — pure client-safe types + `createClientMutationId()`. Mirrors the Server Action payload shapes (`VisitFormValues` in `src/app/(dashboard)/visits/[visitId]/actions.ts`, schedule/pool action inputs) and the data shapes in `src/lib/db/visits.ts`, which are `server-only` and can't be imported client-side. Keep field names in sync with those server-side types. `DraftVisitPayload` carries an optional `expectedVersion` (the revision the client last observed; replayed with the payload so a replayed `completeVisit` is version-guarded — see conflict policy below). `QueuedMutation` is a **discriminated union on `action`** (`saveDraft` | `completeVisit` | `updateVisitStatus` | `createVisit` | `createPool` | `updatePool` | `deletePool`): each variant's `payload` mirrors its Server Action's input shape (the `ActionPayloadMap` type is the single source of truth). Visit-scoped actions (`saveDraft`/`completeVisit`/`updateVisitStatus`, the `VisitScopedAction` union) also carry `visitId`; the rest carry nothing beyond their payload. Shared fields: `status: pending|processing|failed|dead`, `retryCount`, `lastError`, and `nextRetryAt` (backoff schedule, persisted so a reload resumes it). `SyncMeta` is the per-tenant last-synced bookmark (`companyId` + `lastSyncedAt`). `CachedPool` + `PoolCacheSnapshot` mirror `PoolWithLastVisit`'s rendered fields (`lastVisitAt` stored as an ISO string) — the read-cache shape behind the offline pools view. `CachedVisit` mirrors the rendered fields of `getVisitById` (pool header fields, status, `scheduledAt` ISO string, `lastReadings`/`chemicals`/`notes`) — the read-cache shape behind the offline `/visits/{id}` view; `cachedAt` is stamped at save time by `saveVisitCache`.
- `db.ts` — `import "client-only"`; the `poolbench-offline` Dexie schema:
  - `draftVisits: "++id, &[companyId+visitId], companyId, updatedAt"` — one draft per visit per tenant.
  - `mutationQueue: "++id, &[companyId+clientMutationId], companyId, [companyId+status], [companyId+visitId], createdAt"` — unique queue entry per tenant; FIFO drain via `[companyId+status]` + `createdAt`; per-visit reads via `[companyId+visitId]`. `nextRetryAt` is an unindexed field.
  - `syncMeta: "&companyId, lastSyncedAt"` — one row per tenant.
  - `poolCache: "&companyId, cachedAt"` — one last-observed `/pools` snapshot per tenant.
  - `visitCache: "++id, &[companyId+visitId], companyId, cachedAt"` — one last-observed visit per tenant per visit.
  Schema is **v5** (v2 added the `[companyId+visitId]` index; v3 added `syncMeta`; v4 added `poolCache`; v5 added `visitCache`; all backfilled automatically on upgrade). Queue/draft indexes unchanged since v2.
- `sync-meta.ts` — `setLastSyncedAt(companyId, at?)` / `getLastSyncedAt(companyId)`. Stamps a tenant's last successful sync so the offline banner can show a "Last synced <time>" timestamp. `client-only` transitively via `./db`.
- `pool-cache.ts` — **read cache for the offline pools view**: `savePoolCache(companyId, pools, total)` (upsert by `&companyId`, stamps `cachedAt: Date.now()`, one row per tenant — last-write-wins), `getPoolCache(companyId) → PoolCacheSnapshot | null`, `clearPoolCache(companyId)`. Fed by `<PoolsCacheMirror>` (mounted in the server-rendered `/pools` page) and consumed by `<OfflineRouteView>` when `/pools` fails to load offline. `client-only` via `./db`.
- `visit-cache.ts` — **read cache for the offline `/visits/{id}` view**: `saveVisitCache(visit)` (upsert by `[companyId+visitId]` in a readwrite transaction, stamps `cachedAt` — the caller's render can't call `Date.now()`), `getVisitCache(companyId, visitId) → CachedVisit | null`, `clearVisitCache(companyId, visitId)`. Fed by `<VisitsCacheMirror>` (mounted in the server-rendered `/visits/{id}` page) and consumed by `<OfflineRouteView>` when a visit page fails to load offline. `client-only` via `./db`.
- `backoff.ts` — **pure, no I/O**: `MAX_RETRIES` (6), `nextDelayMs(attempt, {base=2000, multiplier=2, cap=300000, jitter=0.2})`, `computeNextRetryAt(now, attempt)`. Tunable schedule consumed only by the processor.
- `draft-visits.ts` — `saveDraft` (upsert by `[companyId+visitId]`), `getDraft`, `listDrafts` (newest first), `deleteDraft`.
- `mutation-queue.ts` — `enqueue` (generic on `action`: visit-scoped actions take `(companyId, action, visitId, payload)`, pool/`createVisit` take `undefined` for `visitId` and their own payload; mints/reuses `clientMutationId`; drops duplicates), `getPending` (FIFO, optional limit), `getPendingForVisit` (pending entries for one visit), `getByClientMutationId`, `markStatus` (status + optional `retryCount`/`lastError`/`nextRetryAt`), `deleteEntry` (single-entry removal after a successful flush), `deleteEntriesForVisit` (all entries for a visit), `getDue(companyId, {now, limit})` (pending + failed entries whose `nextRetryAt` is due or unset, FIFO — queried via the `[companyId+status]` index), `getDead` / `getDeadForVisit` (dead-lettered entries), `countEntriesForVisit` (all-status count — keeps the draft while any entry still holds unsynced edits), `deleteDeadForVisit` (drop a visit's dead entries on re-save), `retryDead` (dead → pending, retryCount 0, schedule cleared), `getStats(companyId) → {pending, processing, failed, dead}` (tenant-level counts), `getVisitStats(companyId, visitId) → {pending, failed, dead}` (per-visit counts for the sync-status badge; scoped via the `[companyId+visitId]` index, `processing` is never persisted so not tallied), `clearCompanyData` (drafts + queue + pools/visits read caches, for sign-out/tenant switch). Per-visit reads guard on `"visitId" in entry` so non-visit entries (pool CRUD, `createVisit`) never match.
- `sync-status.ts` — **pure, no I/O**: `type SyncStatus = "offline" | "pending" | "syncing" | "failed" | "synced"` + `deriveSyncStatus(stats: {pending, failed, dead}, opts: {online, inFlight})` + `SYNC_STATUS_META` (label + semantic tone). Precedence: failed > syncing > pending > offline > synced. Consumed by the visit form's badge/toasts.
- `sw-policy.ts` — **pure, no worker globals** (importable in tests): `isServerActionRequest({method}, {sameOrigin})` (same-origin non-GET), `buildServerActionRules()` (one `NetworkOnly` rule per non-GET method — serwist routes are method-keyed, so `method` is mandatory for a POST guard), `buildRuntimeCaching(baseRules)` (server-action rules prepended to the injected `defaultCache`; `sw.ts` supplies `defaultCache` so this module stays testable without a worker env), `buildFallbacks()` (navigation-only offline fallback → `/offline`, matched on `request.mode === "navigate"` so RSC `cors` requests never get HTML disguised as a payload — those surface to the offline-aware `error.tsx`), `APP_SHELL_PRECACHE` (stable `public/` entries: `/offline` + `/manifest.webmanifest` + icons), `composePrecacheEntries(manifest, shell)` (merge + dedupe by URL, normalizes string entries, tolerates absent dev manifest). Consumed by `src/app/sw.ts`.
- `company-id.ts` — **pure, no I/O**: `COMPANY_ID_KEY` (`"poolbench:companyId"`) + `getCachedCompanyId()` / `setCachedCompanyId()` / `clearCachedCompanyId()`. Client-side mirror of the active tenant the dashboard layout resolves; the `/offline` page and offline banner read it back because the SW-served fallback page can't call `requireTech()`. All no-ops outside the browser (safe to import from SW/server paths). Mirrored by `<IdleRoutePrefetch>` in the dashboard layout.
- `precache-routes.ts` — **pure, no I/O**: `getPrecacheRoutes(role: UserRole) → string[]`. Role-scoped list of static-shape dashboard routes (no dynamic id segment) to warm into the SW cache right after login — base tenant set for TECH, `+ /team + /account/api-keys` for OWNER, a separate admin-only set for SUPER_ADMIN. Deliberately excludes `pools/[poolId]`, `visits/[visitId]`, `admin/companies/[companyId]` — those rely on `pool-cache.ts`/`visit-cache.ts` instead. Consumed by `<AppPrecacheGate>`.
- `app-precache.ts` — `import "client-only"`: `precacheRoutes(routes, onProgress?, fetchImpl = fetch) → Promise<{ total, failedRoutes }>`. Fires two fetches per route — a plain GET (warms the `pages` HTML cache) and a GET carrying an `RSC: "1"` header with no `Next-Router-Prefetch` header (warms the `pages-rsc` cache, the same bucket a real Link click reads from) — so both a soft client navigation and a hard reload resolve offline. `router.prefetch()` doesn't achieve this: it only warms the *separate* `pages-rsc-prefetch` bucket a real navigation never reads. `fetchImpl` is injectable (DIP) for tests; a rejected fetch (offline) counts as a failed route rather than throwing.
- `precache-marker.ts` — `import "client-only"`: `hasPrecached(companyId)` / `markPrecached(companyId)`, backed by a per-`(companyId, PRECACHE_VERSION)` localStorage key. Lets `<AppPrecacheGate>` skip the blocking download screen on every load after the first. Bump `PRECACHE_VERSION` when `precache-routes.ts`'s manifest changes in a way that needs a forced re-download. All no-ops outside the browser.
- `processor.ts` — **queue processor** (`import "client-only"`): `drainOnce(companyId, replay, {now?, limit?, classifyError?, scheduleRetry?, replayTimeoutMs?, onDead?, onSynced?, onFailed?})`. Retry-aware sweep over `getDue`: `replay(entry)` (in-flight tracked in a module-local set, never persisted — a killed app drops it while the entry stays `pending` in IndexedDB, so a reload re-attempts it) → success deletes the entry (and, only for visit-scoped actions carrying a `visitId`, the visit's draft once no entries remain) + `onSynced(entry)` → transient failure `failed` + `retryCount+1` + `nextRetryAt` + `onFailed(entry, false)`; budget exhausted (`>= MAX_RETRIES`) or `classifyError`-permanent → `dead` + `onDead(entry)` + `onFailed(entry, true)`. Guards: no-op while `navigator.onLine === false` (offline spell never consumes retry budget), single-flight (concurrent sweeps skip), and `replayTimeoutMs` (default 30s) bounds each `replay` so a hung fetch can't wedge the guard. `_resetSweepGuardForTests` is the test-only guard reset.
- `src/hooks/use-queue-processor.ts` — `useQueueProcessor({companyId, replay, classifyError?, onDead?, onSynced?, onFailed?, sweepIntervalMs?, enabled?})` — wires the processor's triggers: `useOnlineStatus` (online+hydrated), `visibilitychange` → visible (covers Capacitor WebView resume + PWA tab return), 5s sweep interval; injects `replay`/`classifyError`/`onDead`/`onSynced`/`onFailed`; `enabled: false` (used on completed/other-tech pages) silences every trigger and makes `drain` a no-op; returns `{ drain, inFlight }` — `drain: () => Promise<DrainResult[]>` for an immediate sweep (e.g. after `retryDead`), `inFlight` reflects whether a sweep is running (tenant-wide, drives the "syncing" badge state).

## Tenancy

Same invariant as the server DB layer: every read/write is scoped by `companyId`. Cross-tenant rows can't collide because both unique keys are compound on `companyId`. `clearCompanyData(companyId)` is the sign-out/tenant-switch wipe (drafts + queue + `poolCache` + `visitCache`).

## Status

Write-through draft save is wired into `VisitForm` (`src/app/(dashboard)/visits/[visitId]/visit-form.tsx`): Save Draft persists to Dexie immediately (`saveDraft` + `enqueue`), then drains the queue via `useQueueProcessor` — `replay = (entry) => saveDraftAction(entry.visitId, entry.payload)` — with `classifyError` mapping Zod/access errors (deleted visit, other tech's visit) to permanent so they dead-letter immediately. A re-save calls `deleteDeadForVisit` so a newer save supersedes stale dead entries. Sync-status UI is landed: `useVisitSyncStatus` (`src/hooks/use-visit-sync-status.ts`) derives per-visit status via `getVisitStats` + `deriveSyncStatus`, renders a `SyncStatusBadge` (`src/components/visits/SyncStatusBadge.tsx`) in the actions area, and fires deduped toasts on failure transitions (dead-lettered → `UNSYNCED_COPY` "Re-save or retry", transient → "Will retry automatically"; pre-existing `failed`/`dead` state at page load is seeded and not re-toasted) and on the dirty→clean handoff when back online ("Changes synced"). The dead-letter chip now uses `sync.counts.dead` + `sync.retry()` (= `retryDead` + count refresh + immediate `drain`). `useQueueProcessor`'s `onSynced`/`onFailed` callbacks feed the hook's count refresh + toasts (dead-letter pairs `onDead` with `onFailed(entry, true)`, so the hook wires only `onFailed` to avoid double-count refreshes). Completing a visit still clears its local draft + all queued entries. SW policy is landed: `sw-policy.ts` forces same-origin non-GET requests through `NetworkOnly` (prepended to `defaultCache`) so Server Action POSTs can never be served a stale cached 200, precaches the stable `public/` shell alongside the auto-manifest with `cleanupOutdatedCaches`, and routes uncached offline full-document navigations to the precached `/offline` page via `buildFallbacks()` (navigate-mode only).

## Offline surfaces (landed)

- `src/components/offline/app-precache-gate.tsx` — `<AppPrecacheGate role companyId children>`, mounted around the whole `(dashboard)/layout.tsx` tree. On the first load for a `(companyId, PRECACHE_VERSION)` pair (per `precache-marker.ts`), blocks the dashboard behind a full-screen 0–100% "Getting Poolbench ready…" screen while `precacheRoutes(getPrecacheRoutes(role))` runs, then marks the tenant done and renders `children`. Renders `children` immediately (no blocking screen) if already marked, or if the device is offline at mount — nothing to download, and existing per-page caches already cover the offline fallback in that case.
- `src/components/offline/offline-route-view.tsx` — **unified offline fallback**, rendered by both the `/offline` page and the root `error.tsx`'s offline branch. When the device is offline on `/pools` (or `/pools/…`) and a cached snapshot exists, renders the saved pool rows (read-only, via `PoolRow`) with a "showing the last saved copy" banner instead of the generic copy — **show what you have so far**. Same for `/visits/{id}`: renders the cached visit's header (pool name, status, address, volume, scheduled time) + readings/chemicals/notes, with any local draft edits overlaid. Otherwise renders the standard offline screen. Reloads the page once connectivity returns (offline→online edge) so the real data replaces the cached copy.
- `src/components/offline/pools-cache-mirror.tsx` — client, renders nothing; mounted in the server-rendered `/pools` page. Persists the last-observed pools snapshot (`pools` + `total`) into `poolCache` via `savePoolCache` whenever the page renders, so the offline view has something to show.
- `src/components/offline/visits-cache-mirror.tsx` — client, renders nothing; mounted in the server-rendered `/visits/{id}` page. Persists the last-observed visit snapshot into `visitCache` via `saveVisitCache` whenever the page renders, so the offline view has something to show.
- `src/components/offline/offline-status.tsx` — client; reads `getCachedCompanyId()` + `getStats(companyId)` for a pending-count line, a Retry button that `drainOnce(companyId, DEFAULT_REPLAY)`s the queue (disabled while offline; spinner while draining), and a dashboard link. Shared by the generic and cached-pools offline views.
- `src/components/offline/idle-route-prefetch.tsx` — client, renders nothing; mirrors the tenant into localStorage via `setCachedCompanyId` and prefetches nav routes (`/dashboard`, `/schedule`, `/pools`, `/reports`) during idle (`requestIdleCallback`, timeout fallback) while online so their RSC payloads land in the router + SW runtime caches. Mounted in `(dashboard)/layout.tsx`.
- `src/app/offline/page.tsx` — **static** (`dynamic = "force-static"`) offline fallback page; precached via `APP_SHELL_PRECACHE` and served by the SW navigation fallback when a full document load fails offline (also reachable at `/offline` when online). Renders `<OfflineRouteView>` — when the SW serves it for a `/pools` or `/visits/{id}` navigation, the address bar still reads the intended URL, so the cached pools/visit view kicks in.
- `src/app/error.tsx` — offline-aware root error boundary: when hydrated and offline it renders `<OfflineRouteView>` (a dropped RSC request isn't covered by the navigate-only SW fallback); online errors keep the generic copy + digest + Retry / Go back / Go home.

## Conflict-resolution policy (landed)

**Hybrid: drafts are last-write-wins, completions are version-guarded.**
- `saveDraftVisit` is LWW — the server ignores `expectedVersion`. Drafts are transient replaceable state; the dangerous draft case (visit completed/cancelled elsewhere) is already rejected server-side.
- `completeVisit` rejects with `VisitVersionConflictError` (409, message "This visit was updated on another device…") when `opts.expectedVersion` doesn't match the stored `version`. The guard is atomic — a conditional `updateMany` filtered on the expected revision inside the completion transaction — so a check-then-write race between two concurrent completions can't both pass. A replayed already-applied `clientMutationId` short-circuits BEFORE the guard (idempotent regardless of drift).
- The visit form keeps its known revision in a ref (`knownVersionRef`), seeded from the serialized visit. It re-bases via `useVisitSyncStatus`'s `onReplayApplied` after every successful `saveDraftAction` replay (returns `{ version }`) and re-seeds on `visit.version` prop change (a `router.refresh()` after a conflict or any refresh reflecting a status change/reassignment). `handleSaveDraft` and `handleComplete` both await the queue `drain()` first so the re-base lands before the completion's `expectedVersion` is built. All of this is load-bearing: skipping any piece falsely rejects your own next completion (false self-conflict) or, worse, loops the conflict recovery against a stale revision.
- `handleComplete` matches the conflict message on the client and shows a dedicated toast + `router.refresh()` (reload authoritative state, which re-seeds the revision) instead of the generic save-failed path.
